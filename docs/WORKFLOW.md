# 과제 파악부터 제출까지

과제의 목적과 제출물을 먼저 파악하고, 필요한 해결 방법과 도구를 고른 뒤 구현·검증·제출하는 공통 순서다. 결과물의 형태, 기술 구성, 검증 방법은 실제 요구사항에 따라 정한다.

아래 순서는 작업을 시작할 때의 기본 흐름이다. 새 사실이나 검증 결과로 판단이 바뀌면 앞 단계로 돌아가 계획을 갱신한다.

## 1. 내가 과제 안내와 README 읽기

문제 설명, README, 평가 기준, 제출 안내와 작업 지침을 직접 읽는다. 문서가 여러 개면 서로 다른 조건이 있는지도 확인한다.

- 무엇을 해결하고 무엇을 제출해야 하는지 표시한다.
- 필수 조건, 제공 자료, 제한 사항, 마감·제출 방식을 구분한다.
- 이해되지 않거나 서로 충돌하는 내용을 적어 둔다.

**이 단계의 결과:** 과제 목적과 제출물을 내 말로 설명할 수 있고, 추가 확인할 내용이 정리돼 있다.

## 2. AI에게 안내·요구사항·현재 자료 분석시키기

[첫 프롬프트](FIRST_PROMPT.md)를 사용해 AI가 실제 문서와 파일을 근거로 분석하게 한다. 읽지 않은 내용이나 확인하지 않은 기능을 추측으로 채우지 않도록 한다.

- 필수 / 선택 / 불명확한 요구사항과 근거 위치를 정리한다.
- 제공된 코드·자료에서 재사용할 수 있는 부분과 부족한 부분을 확인한다.
- 내가 읽은 내용과 AI의 해석을 대조한다.

**이 단계의 결과:** 과제 해석을 맞추고, 확인된 사실과 가정을 구분했다.

## 3. 현재 상태와 작업 환경 확인하기

제공된 파일 구조, 사용할 수 있는 도구·버전, 실행·확인 방법을 살핀다. 기존 결과물이나 코드가 있으면 해당 작업에 맞는 최소 확인을 수행한다.

- 이미 되는 것, 안 되는 것, 아직 확인하지 않은 것을 구분한다.
- 실행 가능한 기존 프로젝트는 안내된 방법으로 실행하고 시작 상태를 기록한다.
- 새로 시작하는 과제는 제공 자료와 작업 가능한 환경을 확인한다.

**이 단계의 결과:** 작업의 출발점과 실제로 사용할 수 있는 환경을 안다. 이후 생긴 문제와 처음부터 있던 문제도 구분할 수 있다.

## 4. 중요한 불확실성을 질문으로 해소하기

현업자·고객 역할이나 질의 채널이 제공된 경우, 구현 방향에 영향을 주는 질문부터 묻는다. 문서에 이미 있는 답은 먼저 확인한다.

1. 이 과제에서 가장 먼저 해결해야 할 문제는 무엇인가요?
2. 어떤 상황에서 누가 이 결과물을 사용하거나 평가하나요?
3. 결과가 잘됐다고 판단할 가장 중요한 기준은 무엇인가요?
4. 조건이 충돌하거나 시간이 부족하면 무엇을 우선해야 하나요?
5. 반드시 지켜야 할 조건이나 피해야 할 결과가 있나요?

이해관계자에게는 목적·우선순위·기대 결과를, 환경 지원 채널에는 도구·권한·실행 문제를 확인한다. 질문할 채널이 없거나 답을 받지 못하면 근거가 있는 가정을 명시하고, 변경될 때 영향이 큰 가정부터 관리한다.

**이 단계의 결과:** 중요한 의문을 해결했거나, 남은 가정과 그 영향을 설명할 수 있다.

## 5. 해결할 범위와 성공 기준 정하기

필수 요구사항을 작업 단위로 나누고 우선순위를 정한다. 평가·제출 조건과 연결해 완료 여부를 판정할 방법도 정한다.

- 반드시 끝낼 것, 시간이 남으면 할 것, 이번 범위에서 제외할 것을 구분한다.
- 요구사항마다 기대 결과와 확인 방법을 붙인다.
- 작업 시간에 검증·정리·제출 시간을 포함한다.

**이 단계의 결과:** 무엇을 어느 수준까지 완성할지와, 무엇을 확인하면 완료라고 할지 정해져 있다.

## 6. 해결 방법과 필요한 도구 선택하기

가능한 방법을 간단히 비교하고 현재 조건에서 구현·검증할 수 있는 방법을 고른다. 기존 구성과 제공 자원을 우선 고려한다.

- 선택한 방법의 이유, 필요한 작업, 주요 한계를 정리한다.
- 스킬·라이브러리·공개 코드는 필요할 때만 선택하고 출처·라이선스·규정 적합성을 확인한다.
- 설치 시간, 실행 자원, 추가 의존성, 외부 통신을 확인한다.

[스킬 목록](SKILLS.md)은 선택지다. 과제에 맞는 스킬이 없으면 추가하지 않고 진행해도 된다.

**이 단계의 결과:** 해결 방향과 작업 순서를 설명할 수 있고, 추가 도구마다 필요한 이유가 있다.

## 7. 필요한 개발 환경 준비하고 최소 실행 확인하기

선택한 해결 방법에 맞게 실제로 작업할 환경을 준비한다. 3단계에서 확인한 기존 환경과 프로젝트 설정을 바탕으로, 필요한 준비를 수행한다.

1. **설치·실행 방식 확인:** README와 프로젝트 설정 파일에서 필요한 버전, 패키지, 실행 명령을 확인한다. 기존 프로젝트는 현재 구조와 버전 고정 파일을 따른다.
2. **필요한 패키지 준비:** 이미 설치된 항목을 활용하고 부족한 의존 패키지를 설치한다. 프로젝트별 격리가 필요하면 해당 방식으로 준비한다.
3. **실행에 필요한 설정 준비:** 과제에서 요구하는 설정값, 입력 자료 위치, 출력 경로 등을 맞춘다. 비밀값이 있으면 내용을 출력하지 않고 설정 여부만 확인한다.
4. **작업에 맞는 실행 방법 정리:** 프로그램·스크립트는 실행 명령과 인자를, 웹 화면이 필요한 과제는 실행 중인 서버와 내부 미리보기 연결을 확인한다. 해당하는 항목만 준비한다.
5. **최소 실행 확인:** 안내된 명령을 실행해 시작·입력·출력 등 기본 동작을 확인한다. 기존 검사 명령이 있으면 실행 가능한지 확인하고, 실패한 항목은 원인을 구분한다.
6. **다시 실행할 방법 기록:** 사용한 설치·실행·확인 명령과 필요한 조건을 남긴다.

준비가 끝난 항목은 다음 작업에서 활용한다. 추가 준비가 필요 없는 경우에는 최소 실행과 확인 방법만 기록하고 넘어간다.

**이 단계의 결과:** 필요한 환경이 준비됐고 최소 실행 여부를 실제로 확인했다. 실행 방법과 남아 있는 환경 문제가 정리돼 있다.

## 8. 가장 불확실한 부분을 먼저 작게 확인하기

실패하면 전체 접근을 바꿔야 하는 가정이나 의존성을 찾는다. 그중 영향이 큰 것부터 가장 작은 실험으로 확인한다.

- 무엇을 확인할지와 통과·실패 기준을 먼저 정한다.
- 최소 입력·작업·결과로 실제 환경에서 실행한다.
- 실패하면 원인을 구분하고 방법·범위·계획을 조정한다.

중요한 불확실성이 없다면 별도 실험을 억지로 만들지 않고 구현으로 넘어간다. 실험 결과를 곧바로 전체 과제의 완성으로 간주하지 않는다.

**이 단계의 결과:** 핵심 가정에 근거가 생겼고, 현재 방법으로 진행할 수 있는지 판단했다.

## 9. 핵심 요구사항부터 작은 단위로 구현하기

우선순위가 가장 높은 요구사항부터, 실행해서 결과를 확인할 수 있는 크기로 나누어 구현한다.

- 한 단위의 목적과 기대 결과를 AI에게 명확히 전달한다.
- 변경한 부분을 실행·확인하고 다음 작업으로 넘어간다.
- 중간 결과, 오류, 새로 발견한 조건을 계획에 반영한다.

**이 단계의 결과:** 핵심 요구사항의 결과를 실제로 확인할 수 있다. 여러 부분이 함께 동작해야 한다면 그 연결도 확인했다.

## 10. 전체 결과를 성공 기준과 대조하기

5단계에서 정한 기준으로 결과물 전체를 확인한다. 결과물의 형태에 맞는 검사·테스트·직접 검토 방법을 사용한다.

- 요구사항이 충족됐는지 항목별로 확인한다.
- 중요한 경계 조건·실패 조건과 정확성·사용성·성능 등 해당 과제의 품질 기준을 확인한다.
- 통과 / 실패 / 미확인을 실제 결과에 따라 구분한다.

화면 확인이 필요한 과제라면 제공된 내부 미리보기에서 직접 확인한다. 실행 결과나 파일이 제출물인 과제라면 해당 결과를 확인한다.

**이 단계의 결과:** 충족한 조건과 남은 문제를 근거로 설명할 수 있다.

## 11. 중요한 부족분을 수정하고 다시 확인하기

발견한 문제를 필수 요구사항·평가 영향·남은 시간에 따라 정렬한다. 원인을 확인하고 필요한 범위만 수정한다.

- 결과를 막는 오류와 필수 조건 누락부터 해결한다.
- 수정한 부분과 영향을 받는 관련 부분을 다시 확인한다.
- 선택적 개선은 필수 결과와 제출 준비에 지장이 없을 때 진행한다.

**이 단계의 결과:** 제출을 막는 문제가 해결됐고, 해결하지 못한 한계는 명확히 정리됐다.

## 12. 재현 방법과 구현 설명 정리하기

평가자가 제출물을 사용·실행·확인할 수 있도록 필요한 설명을 남긴다. 내가 결과와 주요 선택을 이해했는지도 점검한다.

- 실행·사용·확인 방법, 필요한 조건, 결과물의 위치를 정리한다.
- 해결 방식, 중요한 선택 이유, 사용한 공개 자료와 남은 한계를 기록한다.
- 제출 대상과 파일 저장 상태를 확인하고 불필요한 민감 정보가 포함되지 않도록 한다.

**이 단계의 결과:** 다른 사람이 결과를 재현·확인할 수 있고, 내가 핵심 작업과 판단을 직접 설명할 수 있다.

## 13. 지정된 방식으로 제출하고 완료 확인하기

제출 안내에 맞춰 필요한 파일·경로·형식을 확인하고 여유 시간을 두고 제출한다.

- 지정된 제출 절차를 완료한다. 저장·실행 성공과 최종 제출 완료를 구분한다.
- 접수·확정·완료 상태가 나뉘어 있으면 각 상태를 확인한다.
- 후속 문답이 있으면 해당 단계의 규정에 따라 본인이 직접 답변하고 최종 종료 상태를 확인한다.

**이 단계의 결과:** 요구된 제출물과 절차가 모두 완료됐다.
