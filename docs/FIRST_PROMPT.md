# 첫 프롬프트 전에 할 일과 첫 요청

## 내가 먼저 할 일

1. 당일 규정, 문제 README, 제출 안내를 직접 읽는다.
2. 과제 목적, 필수 기능, 실행 방법, 제공 자원, 제출물에 표시한다.
3. 모호한 항목을 짧게 적는다. 아직 특정 예시 서비스라고 가정하지 않는다.
4. 제공 AI가 올바른 프로젝트 폴더를 보고 있는지 확인한다.
5. 외부 자료를 쓸 수 있다면 공개 저장소를 가져온다. 개인 파일·키·실제 답안을 반입하지 않는다.

## 첫 프롬프트

아래에서 파일명과 제한 조건은 실제 과제에 맞게 확인한다. 첫 요청의 목적은 이해와 확인이며 구현을 한꺼번에 시작시키는 것이 아니다.

```text
먼저 현재 프로젝트의 README, 요구사항, 평가·제출 안내와 작업 지침 파일을 읽어 줘.
아직 코드 수정, 패키지 설치, 외부 API 호출, 스킬 자동 설치는 하지 마.

다음을 정리해 줘.
1. 사용자가 누구이며 어떤 문제를 해결해야 하는지 한 문장.
2. 필수 기능, 선택 기능, 평가·제출 조건. 근거 파일과 위치를 함께 적기.
3. 현재 코드에서 구현된 부분, 부족한 부분, 실제 확인이 필요한 부분.
4. 언어·프레임워크·패키지와 실행·테스트 방법.
5. 제공 API·DB·파일·마이크 등 필요한 자원과 지원 여부.
6. 현업자에게 우선 질문할 내용과 플랫폼 지원에 확인할 환경 문제.
7. 최소 사용 흐름과 기능별 완료 기준 초안.
8. 구현 전에 먼저 검증해야 할 기술적 제약.
9. 현재 과제에 필요한 공개 스킬만 골라 적용 이유와 주의점 설명.
10. 다음에 할 작업의 순서와 먼저 결정해야 하는 사항.

README의 명시 내용과 너의 추측을 구분해 줘.
환경변수는 이름과 설정 여부만 확인하고 비밀값을 출력하지 마.
개발용 AI가 제공된다고 서비스용 AI API도 제공된다고 가정하지 마.
당일 규정이 스킬의 원문이나 예시보다 우선이야.
다른 AI 연결, 외부로 문제·파일·결과 전송, 화면 자동 조작·캡처,
플랫폼 보안·관리자 설정 변경은 하지 마.
공개 스킬은 선택한 원문과 필요한 참고 문서만 읽고 적용 범위를 설명해 줘.
```

## 답변을 받은 뒤 내가 볼 것

- 내가 읽은 README와 필수 기능 목록이 일치하는가?
- 과제에 없는 기능이나 기술을 AI가 추가하지 않았는가?
- 제공된 API와 확인하지 않은 API를 구분했는가?
- 당장 묻지 않아도 되는 질문보다 사용자 가치·필수 조건 질문이 먼저인가?
- 최소 흐름을 실제로 검증할 수 있는 완료 기준이 있는가?

여기서 필요한 질문에 답하고 구현 범위를 정한 뒤, 현재 단계의 작업을 시작시킨다. 이 프롬프트는 비공개 시험 안내나 실제 문제를 포함하지 않는 일반 준비용 문서다. 반입 가능 여부와 사용 방식은 당일 규정을 따른다.
