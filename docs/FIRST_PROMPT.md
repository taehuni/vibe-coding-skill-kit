# 첫 프롬프트 전에 할 일과 첫 요청

첫 요청은 과제의 목적·조건·현재 상태를 AI와 함께 파악하기 위한 것이다. 결과물의 형태와 기술은 실제 요구사항을 읽은 뒤 정한다.

## 내가 먼저 할 일

1. 당일 규정, 문제 설명, README, 평가·제출 안내를 직접 읽는다.
2. 해결할 문제, 필수 조건, 제공 자료, 제출물과 마감을 표시한다.
3. 모호하거나 충돌하는 내용을 적어 둔다.
4. 제공 AI가 올바른 작업 폴더와 자료를 보고 있는지 확인한다.
5. 첫 요청에서 분석할 범위를 정한다. 외부 자료·추가 도구는 필요성을 확인한 뒤 선택한다.

## 첫 프롬프트

아래 내용의 문서명과 제한 조건은 실제 과제 안내에 맞춘다. 문서나 기존 코드가 없으면 없다고 구분하게 한다.

```text
현재 과제의 문제 설명, README, 요구사항, 평가·제출 안내와 작업 지침을 읽고,
제공된 파일을 조사해서 과제와 현재 상태를 분석해 줘.
아직 코드·파일 수정, 패키지 설치, 외부 전송이나 추가 도구 연결은 하지 마.

다음을 정리해 줘.
1. 해결해야 할 문제와 기대하는 결과물.
2. 필수 조건, 선택 사항, 평가·제출 조건과 각 근거 위치.
3. 제공된 코드·자료에서 확인되는 현재 상태와 부족한 부분.
4. 적용되는 환경·도구·자원 제약과 실행·확인 방법.
5. 중요한 불명확 사항과 우선 질문할 내용.
   현업자에게 물을 문제와 환경 지원에 확인할 문제를 구분하기.
6. 작업 범위, 우선순위, 요구사항별 완료 기준 초안.
7. 가능한 해결 방법과 구현 전에 먼저 확인할 핵심 가정.
8. 다음 작업 순서와 필요한 결정.

문서에 명시된 사실, 파일에서 확인한 사실, 너의 추측을 구분해 줘.
확인하지 못한 내용은 미확인으로 표시해 줘.
결과물의 형태나 특정 기술을 미리 가정하지 말고 요구사항에서 판단해 줘.
스킬·라이브러리·공개 코드가 필요하면 이유와 적용 범위를 먼저 제안해 줘.
적합한 추가 도구가 필요 없다면 없다고 해도 돼.
환경변수나 인증 정보가 있으면 비밀값을 출력하지 마.
과제 안내의 제약 조건을 따라 줘.
```

## 답변을 받은 뒤 내가 볼 것

- 과제 목적과 제출물이 내가 읽은 안내와 일치하는가?
- 필수 조건과 AI가 제안한 추가 사항을 구분했는가?
- 확인한 사실과 추측을 구분했는가?
- 질문의 답이 작업 범위나 해결 방법을 바꾸는가?
- 완료 기준으로 실제 결과를 판정할 수 있는가?
- 도구와 기술을 고른 이유가 요구사항과 연결되는가?

해석 차이와 중요한 질문을 정리한 뒤 작업 범위와 다음 행동을 확정한다. 사용 방식은 당일 규정을 따른다.
